# fix-0005 — Four small advisories from the Phase 0 gate: stale-host hint, TLS error log, tailnet state directory, macOS service wording

- **Type:** fix | **Risk:** low | **Priority:** p1
- **Coder:** claude-code/opus-5-5 | **Date:** 2026-11-28
- **Plan:** .metis/plans/phase-0-plan.md Workstream 0.7: Node role, registration and heartbeat

## Goal

Close four Phase 0 gate advisories (f-018, f-011, f-013, f-010) so a
node's failures say what is wrong, the host's TLS warnings name the peer,
the tailnet client writes nothing outside the state directory, and the
README states macOS service behaviour accurately.

## Fixes

1. **f-018, stale-host hint.** `PeerAddr` gains `Online` (from the tailnet
   status). The node's host dial (`cmd/gaia/node.go`) replaces
   `refusedHint` with `dialHint(err, host, peer)`: a refusal keeps today's
   hint; a timeout (context deadline or a net timeout) gets a hint naming
   `--host` and its device, saying the tailnet reports it offline (when
   `Online` is false) or that it did not answer on port 443, so it is
   offline or not a Gaia host, and pointing at the `gaia-<machine name>`
   host name. `DialTimeout` (5 s) is shorter than the request timeout
   (15 s), so the dial error, hint included, is what the retry log shows.
2. **f-011, TLS error log.** tsnet's netstack connections return a nil
   `RemoteAddr` once the peer has reset the connection, which a failed TLS
   handshake does, so `http.Server` logs `from %!s(<nil>)`. `ListenTLS`
   wraps the tsnet listener so each accepted connection keeps the remote
   and local addresses read at accept time. Fixed in `internal/net`, where
   the tsnet listener is made; `internal/host` is unchanged.
3. **f-013, tailnet state directory.** The directory comes from
   `ipnlocal.NewLocalBackend` → `sockstatlog.NewLogger(logpolicy.LogsDir(..))`,
   which creates `~/.local/share/tailscale` (Linux) or
   `~/Library/Caches/Tailscale` (macOS) unless `TS_LOGS_DIR` names an
   existing directory. `Join` sets `TS_LOGS_DIR` to `<state>/tsnet` before
   starting tsnet. It is process-wide; a daemon runs one tailnet client.
   README's State line notes that the tailnet client's own files all live
   under `<state>/tsnet`.
4. **f-010, macOS wording.** README "Running as a service": on Linux the
   unit survives logout and reboot with lingering on (as already stated);
   on macOS the LaunchAgent runs in your login session: it stops at logout
   and starts again at your next login (not at boot). The LaunchAgent
   mechanism is unchanged.

## Definition of Done

- A host dial that times out returns an error that names `--host`, the
  device, and says it is offline (or did not answer, so offline or not a
  Gaia host). A refusal keeps the fix-0003 hint. Other errors unchanged.
- An `http.Server` behind `ListenTLS`'s wrapper logs a TLS handshake
  failure with the peer address even when the underlying connection's
  `RemoteAddr` has gone nil.
- A tailnet join with `HOME` and cache variables pointed at an empty
  directory creates nothing there; `TS_LOGS_DIR` is the tsnet directory.
- README states macOS logout/next-login behaviour.
- Findings f-018, f-011, f-013, f-010 resolved with evidence.
- `metis verify --post` is green.
