# fix-0003 — On a machine already on the tailnet, Gaia's devices get suffixed tailnet names, so README's --host and node: steps fail

- **Type:** fix | **Risk:** medium | **Priority:** p0
- **Coder:** claude-code/opus-5-5 | **Date:** 2026-11-28
- **Plan:** .metis/plans/phase-0-plan.md Workstream 0.7: Node role, registration and heartbeat

## Goal

Make README's host and node steps work unedited on machines that already run Tailscale, per the Human's decision of 2026-11-28 (slice notes): Gaia daemons ask for `gaia-<machine name>` by default, `gaia host` gains `--name`, and the tailnet name the control server actually assigns is logged at start, shown by `gaia nodes`, and is what `node:` allowlist entries match.

## Architectural context

- `cmd/gaia/daemon.go` (`runHost`, `startTailnet`, `machineName`), `cmd/gaia/node.go` (`runNode`, `nodeDaemon`), `cmd/gaia/service.go` (`parseServiceArgs`).
- `internal/net.Tailnet`: `Join`, `WhoIs` (gives `Peer.NodeName`, the control-server-asserted MagicDNS short name), `LookupPeer`. Gains `Self(ctx)`: this daemon's assigned short and MagicDNS names.
- `internal/host.Allowlist`: `node:` already matches `Peer.NodeName` from WhoIs (control-asserted, never the self-claimed registry name). Unchanged; documented.
- `internal/host.Server.Register` / `registerHTTP`: the registry row gains `tailnet_name`, set from WhoIs on the tailnet (the body's value is ignored there), and from the host's own `Self` for the in-process node.
- `internal/store`: migration `0002` adds `nodes.tailnet_name TEXT NOT NULL DEFAULT ''`.
- `internal/core.Node` / `RegisterNodeRequest` gain `tailnet_name` (additive to API v1; the nodes fixture follows).
- Name resolution (new, `cmd/gaia/name.go`): `--name` if given; else the name recorded in `<state>/name`; else, for a state directory joined (tsnet state) or used (host `gaia.db`) before this fix, the old default (the machine name), so existing installs keep their name; else `gaia-<machine name>`. The resolved name is recorded in `<state>/name` (0600). The registry name and the requested tailnet name are this one name; for `gaia host --node` the in-process node registers under it too.
- ADR-0004 (tailnet, stable names), ADR-0002 (one binary, two roles).

## Definition of Done

- With no `--name`, a fresh state directory makes `gaia host` and `gaia node` ask the control server for `gaia-<machine name>` (cut to a valid 63-character label); the machine's own Tailscale device keeps its name, so the two no longer collide.
- `gaia host --name NAME` exists, is validated like `gaia node --name`, and `gaia service install host --name NAME` passes it to the unit.
- A state directory with tsnet state (or, for the host, a registry) and no recorded name keeps the old default name (the machine name); a recorded name is reused; `--name` overrides and is recorded.
- Each daemon logs, once joined, the tailnet name and MagicDNS name the control server assigned, and warns, saying which `--host` / `node:` to use, when the assigned name differs from the requested one.
- `gaia nodes` (text and `-o json`) shows each node's assigned tailnet name (`tailnet_name`); the host sets it from WhoIs, never from the request body.
- `node:` allowlist entries match the assigned tailnet name (behaviour unchanged, now documented and tested).
- When `--host` resolves to a device where nothing answers on 443, the node's retry log says so and points at the `gaia-` default and the host's logged tailnet name.
- README states exactly which name `--host` and `node:` take, uses `gaia-` names in its examples, and says how an existing state directory re-joins under the new name. The nodes fixture and launcher contract examples follow.
- `metis verify --post` is green.
